# 踩坑清单（Pitfalls）

> 格式：现象 → 根因 → 解法 → 举一反三。Agent 每次踩坑必须追加；面试弹药库之一。

| 日期 | 现象 | 根因 | 解法 | 举一反三 |
|---|---|---|---|---|
| 2026-08-06 | iTunes Search API 对 200 首中文歌回填命中 0 | ChineseLyrics 是中文歌名/歌手，iTunes 曲库中文歌 trackName/artistName 是英文（Jay Chou/Nocturne），精确匹配必然失败 | 弃用 iTunes，改用中文覆盖最好的网易云 API；先跑子集验证匹配率再全量 | 数据匹配类任务，先验证"名称空间"是否一致，别盲目全量 |
| 2026-08-06 | 网易云搜索接口连续请求 100 次后返回 code 405「操作频繁」 | 搜索接口风控严格（比详情接口敏感），0.8s 间隔仍触发 | 间隔提到 2s+，对 405/460/462 指数退避 45s；子集验证后再全量 | 免费接口先探风控阈值，脚本内置退避是标配 |
| 2026-08-06 | DeepSeek JSON mode 下要求"输出 JSON 对象"，10 首只解析出 2 首 | prompt 让模型输出单对象，但批次内多首歌曲需要数组；解析逻辑与输出格式不匹配 | prompt 明确"输出 JSON 数组，顺序对应输入"；max_tokens 按批大小放大（10 首 1800） | LLM 结构化输出的 prompt 必须与解析逻辑强契约，先小样本验证格式 |
| 2026-08-06 | ChineseLyrics 歌名残留《》与「原创 demo」后缀 | 歌名清洗先做全匹配《》失败（带后缀） | 先剥后缀再处理《》（非全匹配 sub），\xa0 归一为空格 | 清洗顺序影响结果：先删杂质再结构化处理 |
